## 3. Congelamiento: réplica detenida con réplica síncrona

$ IP_PUBLICACION_DB=127.0.0.1 docker compose -p zonalia-n3 --profile n3 stop db-replica
 Container zonalia-n3-db-replica-1  Stopping
 Container zonalia-n3-db-replica-1  Stopped

$ perl -e 'alarm 8; exec @ARGV' docker compose exec -T db psql -U zonalia_admin -d zonalia   # macOS no trae timeout; esto corta a los 8 s -c "INSERT INTO prueba_sync VALUES (99)"

(código de salida: 130; tardó 191 s)

$ docker compose exec -T db psql -U zonalia_admin -d zonalia -Atc "SELECT pid, state, wait_event_type, wait_event, query FROM pg_stat_activity WHERE query LIKE 'INSERT INTO prueba_sync VALUES (99)%'"
201|active|IPC|SyncRep|INSERT INTO prueba_sync VALUES (99)

$ docker compose exec -T db psql -U zonalia_admin -d zonalia -Atc "SELECT count(*) FROM prueba_sync WHERE i = 99"   # visto desde otra sesión mientras espera
0

$ IP_PUBLICACION_DB=127.0.0.1 docker compose -p zonalia-n3 --profile n3 up -d --wait db-replica
 Container zonalia-n3-db-replica-1  Healthy

$ docker compose exec -T db psql -U zonalia_admin -d zonalia -Atc "SELECT count(*) FROM prueba_sync WHERE i = 99"
1

$ docker compose exec -T db psql -U zonalia_admin -d zonalia -Atc "SELECT count(*) FROM pg_stat_activity WHERE wait_event = 'SyncRep'"
0

$ IP_PUBLICACION_DB=127.0.0.1 docker compose -p zonalia-n3 --profile n3 exec -T db-replica psql -U zonalia_admin -d zonalia -Atc "SELECT count(*) FROM prueba_sync WHERE i = 99"
1

Nota: el `alarm 8` de perl no cortó el cliente (docker compose ignora SIGALRM). El INSERT se quedó esperando 191 s hasta que terminé el cliente a mano con `kill -TERM` (código 130). En el primario la sesión siguió activa en espera `IPC / SyncRep` y la fila 99 no era visible para otras sesiones. Al levantar la réplica, el commit se completó solo: la fila 99 aparece en el primario y en la réplica, y no queda ninguna sesión en SyncRep.
